# MLagent v0.4 Stage 2 Continuation Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each issue-specific plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete GitHub Issues #9-#16 so the approved v0.4 PRD is delivered as one recoverable Claude Code plugin workflow with all six UI modules.

**Architecture:** Continue extending the existing deterministic `DomainCore` boundary and schema-versioned Team Memory assets. Deliver one narrow end-to-end tracer bullet per GitHub Issue; every issue receives its own design and implementation plan before production code, and adapters remain thin.

**Tech Stack:** Python 3.11+, dataclasses, pathlib, JSON/JSONL, ordinary Git, nbformat, scikit-learn/XGBoost, Streamlit, Claude Code Skills/Hooks, pytest.

---

## 1. Delivery rules

- This is the cross-issue roadmap, not a substitute for an issue-specific design and implementation plan.
- Start from the latest tip of `feat/issue-8-sop-promotion` for Issue #9, then stack later work on the latest accepted delivery branch.
- Keep one Issue per branch and worktree.
- Add behavior through `DomainCore`; do not create parallel rules in CLI, Hooks, frontend services, or Streamlit.
- Use immutable or append-only authoritative assets and typed provenance. Local Index remains disposable.
- Use TDD for every behavior change and commit in reviewable increments.
- Do not mark an Issue complete until focused tests, the full suite, static checks, and applicable browser acceptance pass.

- mobile `390x844`
- no page-level horizontal overflow
- no browser console warning/error
- all new command, loading, empty, success, failure, permission and recovery states

- [ ] Review implementation against the Issue body and v0.4 PRD.
