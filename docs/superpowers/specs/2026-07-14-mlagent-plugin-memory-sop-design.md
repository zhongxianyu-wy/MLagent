# MLagent Claude Code 插件记忆与 SOP 重设计

> 日期：2026-07-14  
> 状态：用户已确认  
> 适用项目：MLagent_v3  
> 产品形态：Claude Code 插件

## 1. 设计结论

MLagent 继续以 Claude Code 插件作为主入口和交付形式。插件提供 Skills、Hooks、
命令与本地 Web UI，并调用独立的领域核心完成数据认知、训练、记忆、SOP、模型和
Git 操作。

团队记忆仓库与插件代码仓库分离。记忆仓库中的结构化文件是唯一事实来源，本地
查询索引可删除、可重建，不参与 Git 同步，也不能反向覆盖权威记录。

## 2. 核心原则

1. 原始事实、专家经验、训练 SOP 是三种不同资产。
2. 经验只服务于后续探索，不产生 SOP，也不属于 SOP 来源。
3. SOP 只能来源于一个已实际执行完成的训练实例。
4. Notebook 必须先解析并复现成训练实例，才能生成 SOP 候选。
5. 正式 SOP 必须在相同条件下完成独立复现，主指标六位小数完全一致。
6. 正式模型版本只与已批准 SOP 版本关联。
7. 权威资产不可原地覆盖，修改通过新增版本或勘误记录表达。
8. Git 同步只处理新增或变化对象，不重新克隆整个仓库。
9. UI 可以审核和编辑代码，但运行中的训练实例固定使用启动快照。
10. Claude Code 会话是证据来源，不是正式记忆数据库。

## 3. 总体架构

```text
Claude Code
  -> MLagent 插件层
       -> Skills 与 Hooks
       -> 领域核心
            -> 数据与任务认知
            -> 探索与训练执行
            -> 记忆与谱系服务
            -> SOP 与模型服务
            -> Git 同步服务
       -> 本地 Web UI

领域核心
  <-> 团队共享记忆仓库（唯一事实来源）
  -> 本地可重建索引
  -> Web UI 查询与实时事件
```

### 3.1 插件层

插件负责安装、命令入口、Skill 发现、Hook 触发、权限接入和 UI 生命周期。插件不直接
拼接权威记录，也不直接修改已批准 SOP 或正式模型。

### 3.2 领域核心

领域核心提供稳定的命令和服务契约，负责所有校验和写入。训练和指标必须由确定性
执行逻辑产生，不能由语言模型编造或手工填充。

### 3.3 团队记忆仓库

仓库保存项目数据、原始运行包、训练实例、经验候选、可信经验、Notebook 导入记录、
SOP 候选、正式 SOP、审批记录和正式模型。仓库采用普通 Git，预计单文件小于
100 MB，长期总量小于 20 GB。

### 3.4 本地索引

索引用于全文检索、状态计算、谱系遍历和 UI 查询。索引不提交 Git；损坏时从权威文件
完整重建。未来可以增加语义索引，但其结果仍不能成为事实来源。

## 4. 领域资产

### 4.1 数据集版本

每个版本保存实际标准化特征、标签、拆分文件、数据清单、任务类型、评价协议和稳定
指纹。二分类和多分类属于 MVP，回归不在本轮范围。

### 4.2 原始运行记录

每次会话或训练任务生成不可变运行包，只保存关键事实：

- 运行身份、时间、用户和会话引用。
- 数据集、标签、任务与评价协议。
- 用户批准的探索方案。
- 每轮假设、主要改动方向、父实例、代码、配置和随机种子。
- 指标、错误摘要、停止原因和结论。
- 必要证据与保留运行模型。

默认不保存完整对话和完整 stdout/stderr。只有支撑结论、异常或人工决策的片段作为
证据附件保存。

探索方案属于运行前后的普通工作流记录，不建立 SOP 式不可变版本库。Claude Code 根据
用户方向完善方案并生成候选代码；用户确认绑定当前方案与代码指纹。确认后内容变化必须
重新确认，最终执行快照在训练启动后冻结到对应运行和训练实例证据中。

### 4.3 训练实例

每个完成的训练轮次都是独立训练实例。训练实例必须包含数据版本、完整代码、环境、
参数、随机种子、拆分、指标、预测结果、模型指纹和保留决策，并说明本轮优化背景和
主要改动。

baseline、阶段最佳和人工明确标记的模型保留在运行包；未被选中的中间模型默认只保留
指标、指纹和必要证据，不作为长期大文件进入权威仓库。

### 4.4 专家经验

会话结束后，系统从本次新增事实中提炼经验候选。经验描述成功规律、失败模式、适用
条件、推荐动作和风险，并引用原始证据。

待审核经验可以作为低置信度提示参与探索，但必须显式标注，且不能生成或修改 SOP。
人工批准后创建可信经验；拒绝、冲突和替代关系均保留不可变审核记录。

正式 Experience 事件从 schema 2 开始保存事件指纹和前序事件指纹。每条经验的
数据集、运行、训练实例和终止原始记录必须组成同一条可验证谱系；训练实例的冻结输入
还必须与清单指纹、运行会话、数据集版本、内容指纹和版本指纹一致。Stop 在写入任何
候选或结束记录前先完成本次全部候选的谱系预检，否则本次提取不产生权威资产。

Run 事件当前写入 schema 3，并只读兼容 schema 1 和 schema 2。缺少规划会话绑定的
历史 Run 可用于回溯和关闭，但不提供恢复执行，也不可继续追加训练实例；继续探索必须
创建新的已批准 Run。

### 4.5 SOP

SOP 只能从用户指定的训练实例生成：

- 智能体运行实例可直接进入完整性检查。
- Notebook 必须先导入、解析、补齐执行条件并复现为训练实例。
- 候选 SOP 必须在相同数据、代码、配置和环境指纹下独立重训练。
- 主指标按六位小数比较，必须完全一致。
- 任意一名授权成员批准后，才能创建正式 SOP 版本。

SOP 修改只生成新版本，不覆盖旧版本。SOP 在新数据上的执行只生成新的运行和候选
模型，不自动升级 SOP。

### 4.6 正式模型

正式模型版本库只保存已批准 SOP 的关联模型。每个模型记录关联 SOP、来源实例、
数据集、模型指纹、性能、训练策略、优化背景和审批信息。

正式模型默认采用通过独立复现门的模型。来源实例模型继续保留在来源运行包，不重复
登记为同一 SOP 版本的正式模型。

探索过程中的 baseline、阶段最优和人工标记模型可以保留在原始运行包中，但不进入
正式模型版本库。

## 5. Skills 与 Hooks

### 5.1 Skills

MVP 保留六个工作流 Skill：

1. `bootstrap-memory`
2. `intake-data`
3. `design-and-explore`
4. `retrain-from-sop`
5. `review-experience`
6. `instance-to-sop`

Skill 只负责触发条件、工作顺序和人工决策门。解析、训练、指标和写入由领域核心执行。
训练 SOP 是领域资产，不是 Claude Code Skill。

### 5.2 SessionStart

启动时检查仓库与 SSH 配置，增量同步远端，更新本地索引，展示待审核经验，检索相关
可信经验和低置信度经验，并启动或确认 UI。

### 5.3 PreToolUse

阻止直接修改已批准 SOP 和正式模型，阻止绕过领域核心写入权威记录，并阻止未批准
探索方案直接执行训练。

### 5.4 PostToolUse

只捕获训练脚本修改、训练执行、指标和模型等关键动作。不复制普通文件查看、无关对话
和完整工具输出。

### 5.5 Stop

结束时封口运行记录，校验关键字段，从本次新增事实中提炼经验候选，提交插件管理的
新增资产并增量推送。无经验时不创建空经验。推送失败时保留本地待同步状态。

## 6. UI 设计

UI 使用左侧导航提供六个一级模块。

### 6.1 代码审核

提供代码文件树、编辑器、版本差异、修改审计和真实 Claude Code CLI 入口。用户既可在
CLI 中输入提示词让 Claude 修改，也可直接编辑代码。运行中的实例使用冻结快照；编辑
只形成下一候选版本，不热替换当前训练。

### 6.2 数据集概览

展示 Pandas 风格的头尾数据预览，中间省略；同时展示数据版本、结构、缺失、标签分布、
任务类型、拆分和评价指标。

### 6.3 运行状态

展示已批准方案、当前状态、轮次、耗时、每轮主要优化方向、性能曲线、当前最佳实例、
目标性能和停止条件。支持选择历史运行并按时间回放；选择 SOP 后，可叠加同指标历史
基线并展示当前最佳实例的差值。

### 6.4 SOP 概览

展示 SOP 及其版本、来源实例、数据版本、性能、时间、训练策略摘要、优化背景、正式
模型和复现状态。

### 6.5 经验审核总结

展示候选经验、可信经验、证据、冲突与替代关系，并允许授权成员修改表述、批准或拒绝。

### 6.6 谱系回溯

提供图形关系和时间线，支持在数据、运行、实例、经验、Notebook、SOP 和模型之间双向
跳转。经验和 SOP 分别展示，不创建不存在的派生关系。

## 7. Git 同步

同步采用追加优先和唯一 ID，降低多人冲突。SessionStart 只获取缺失对象；本地落后时
快进，本地领先时推送，双方新增时合并互不冲突文件。文件冲突必须停止自动同步，禁止
强推和自动覆盖。

Stop 只暂存插件管理目录，不对整个工作区执行全量暂存。远端不可用时本地继续工作，
所有新增资产保持待同步。SSH 私钥和本地索引不进入仓库。

## 8. 故障与恢复

- 训练失败保留失败实例，不生成 SOP。
- 未封口运行在下次启动时恢复或关闭。
- 索引损坏时从权威文件重建。
- UI 故障不阻塞训练和记忆。
- Notebook 复现失败时只保留导入和失败记录。
- SOP 指标不一致时禁止批准和生成正式模型。
- Git 冲突时停止自动推送，保留本地提交。

## 9. MVP 分期

### 阶段一：可信记忆闭环

插件骨架、共享仓库、Git 同步、数据认知、先设计再探索、训练实例、原始记录、经验提炼、
人工审核和本地索引。

### 阶段二：SOP 与模型闭环

实例转 SOP、Notebook 复现、独立复现门、审批、SOP 版本、正式模型和严格重训练。

### 阶段三：六模块 UI

代码审核与 CLI、数据集概览、运行状态、SOP 概览、经验审核和谱系回溯。

## 10. 非目标

MVP 不将 mem0、MLflow、向量数据库或 AIDE 设为必需依赖；不做自动批准、回归、深度
学习、后台自主实验、文献自动调研、Git LFS、远程公网 UI 和运行中代码热替换。

## 11. 验证重点

1. 所有正式 SOP 和模型的谱系引用完整。
2. 相同条件复现时主指标六位小数完全一致。
3. 待审核经验不能生成 SOP。
4. Git 推送失败后本地资产零丢失。
5. UI 修改代码不会影响运行中的实例。
6. 本地索引可从空状态完全重建。
