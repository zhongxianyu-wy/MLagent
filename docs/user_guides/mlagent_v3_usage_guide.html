1. 当前可测范围

功能 当前状态 推荐测试方式 说明
LLM 问答 可直接运行 交互 CLI：/ask 已切换为 MiniMax OpenAI-compatible 协议，并通过真实请求。
数据接入 Intake 可直接运行 one-shot CLI：intake 支持清晰 CSV 输入，生成标准化 manifest、训练特征、训练标签和 intake report。
随机划分 可直接运行 intake --split-strategy random 生成训练集和测试集文件；小样本划分已做保护。
特征探索 Explore 可直接运行 one-shot CLI：explore --manifest-path 当前真实训练使用 sklearn logistic regression + k-fold，轮次策略覆盖预处理和特征子集选择方向。
Slash command harness 服务层可验证 pytest 或 Python snippet /train_type1 能确定路由到 explore harness；默认交互 shell 尚未注入 RunService。
Plan 模式 服务层可验证 Python snippet / contract test 能生成 validation plan 和开放问题；默认 shell 目前不会漂亮展示非 chunks 返回。
Skill 复现 服务层可验证 pytest / adapter snippet StrictSkillReproductionAdapter 已能读取 manifest 并写 summary/metrics；main 的 reproduce one-shot 入口目前只转发 factory。
Skill 沉淀 服务层可验证 pytest / generator snippet Notebook 到 SkillCandidate 草稿已实现；人工审核、发布入口仍是服务层。
调研 预留边界 服务层返回 unavailable MuyuSearchClient 边界存在，但当前项目内客户端未连接真实 MCP。
前端 API 契约可验证 ApiRouter contract test 不是 FastAPI/HTTP server，仅是前端 API 路由契约对象。
重要：当前最适合做“真实 NGS 特征矩阵实验”的入口是 one-shot CLI 的 intake + explore。默认 uv run python -m src.agent.main 交互 shell 现在适合先测 LLM ask，不适合直接测完整 agent 执行链。

2. 环境准备

2.1 进入项目目录

cd /Volumes/exp/project/MLagent_v3

2.2 安装或同步依赖

uv sync

如果遇到 uv 缓存目录权限问题，可在 Codex 环境中允许 uv run 访问用户缓存；在普通终端通常不会遇到这个沙箱问题。

2.3 确认 Python 入口可用

uv run python -m src.agent.main status

预期：命令静默成功，退出码为 0。

2.4 查看当前配置摘要

uv run python -c "from src.provider.config import load_provider_config; c=load_provider_config(); print(c)"

预期包含：

  • provider_name='minimax'
  • base_url='https://api.minimaxi.com/v1'
  • api_key_env='MINIMAX_API_KEY'
  • model='MiniMax-M2.7'
  • api_protocol='openai-completions'

3. LLM / MiniMax 配置验证

当前项目使用 OpenAI-compatible chat completions 请求：

  • Base URL：https://api.minimaxi.com/v1
  • 接口路径：/chat/completions
  • 鉴权方式：Authorization: Bearer $MINIMAX_API_KEY
  • 模型：MiniMax-M2.7

3.1 最小真实请求

uv run python -c "from src.provider.client import LLMClient; from src.provider.config import load_provider_config; c=load_provider_config(); client=LLMClient(c); print('provider', c.provider_name); print('protocol', c.api_protocol); print('base', c.base_url); print('model', c.model); print('has_key', bool(client.api_key)); print('response', ''.join(client.stream('请只回复 ok'))[:500])"

预期输出最后一行：

response ok

3.2 测试响应过滤

MiniMax 有时会把 <think>...</think> 放入正文。项目已在 OpenAI-compatible 响应中做过滤，CLI 应只显示最终回答。

4. 交互 Shell 测试

4.1 启动交互 shell

uv run python -m src.agent.main

看到提示符后输入：

mlagent> /ask 你是什么模型？

预期：返回 MiniMax 模型生成的自然语言回答。退出 shell：

mlagent> /exit

4.2 默认 shell 当前限制

默认 shell 当前只注入了 LLM，没有注入 RunService 和 harness registry。所以：
  • /ask：可直接测。
  • /plan：服务层能生成 plan，但默认 shell 不会展示 plan dict。
  • /agent、/train_type1、/explore：默认 shell 中会因为缺少 run service 而不适合直接执行。

4.3 Slash command 路由服务层验证

uv run pytest tests/integration/test_train_type1_routing.py -q

预期：

1 passed

这证明 /train_type1 用 demo 做特征探索，目标 AUC 会强制路由到 explore harness，并保留自然语言尾部。

5. 数据接入与标准化

5.1 输入文件要求

当前自动识别支持 CSV 文件，推荐目录内包含：

  • features.csv：第一列为 sample_id，其余列为数值特征。
  • labels.csv：包含 sample_id 和 group。

内置 fixture 位于：

tests/fixtures/data_intake/clear

5.2 训练集-only 标准化

uv run python -m src.agent.main intake \
  tests/fixtures/data_intake/clear \
  --output-root experiments/standardized \
  --split-strategy train_only

预期生成：

experiments/standardized/clear/manifest.json
experiments/standardized/clear/train_features.csv
experiments/standardized/clear/train_labels.csv
experiments/standardized/clear/intake_report.md

5.3 随机划分训练集/测试集

uv run python -m src.agent.main intake \
  tests/fixtures/data_intake/clear \
  --output-root experiments/standardized_random \
  --split-strategy random \
  --split-ratio 0.25 \
  --random-seed 42

预期额外生成：

experiments/standardized_random/clear/test_features.csv
experiments/standardized_random/clear/test_labels.csv

5.4 查看 manifest

cat experiments/standardized/clear/manifest.json

重点检查：

  • dataset_id 是否正确。
  • sample_id_col 是否为 sample_id。
  • label_col 是否为 group。
  • train_feature_path 和 train_label_path 是否指向真实文件。

5.5 模糊输入的苏格拉底式状态

模糊 fixture：

tests/fixtures/data_intake/ambiguous

当前 one-shot CLI 遇到未 ready 的 inspection 会返回退出码 2，不会进入多轮问答。服务层支持 answer_clarification，可用测试验证：

uv run pytest tests/contract/test_data_intake.py -q

6. 特征探索训练

6.1 先准备 manifest

uv run python -m src.agent.main intake \
  tests/fixtures/data_intake/clear \
  --output-root experiments/standardized \
  --split-strategy train_only

6.2 跑 1 轮真实探索

uv run python -m src.agent.main explore \
  --manifest-path experiments/standardized/clear/manifest.json \
  --max-rounds 1 \
  --output-root experiments/outputs

预期生成：

experiments/outputs/explore-clear/run_summary.json
experiments/outputs/explore-clear/rounds.jsonl
experiments/outputs/explore-clear/best_config.json
experiments/outputs/explore-clear/metrics.json

6.3 跑多轮探索

uv run python -m src.agent.main explore \
  --manifest-path experiments/standardized/clear/manifest.json \
  --max-rounds 6 \
  --output-root experiments/outputs

当前轮次策略会循环以下方向：

  • 预处理：由 src/training/preprocessing.py 规划。
  • 特征子集选择：low_variance、correlation_filter、statistical_test、model_importance、recursive_selection、stability_selection。

训练模型当前为 sklearn logistic regression，k-fold 默认是 2。阈值由训练集 k-fold validation 预测选择。

6.4 查看每轮 trace

cat experiments/outputs/explore-clear/rounds.jsonl

重点检查字段：

  • exploration_direction
  • preprocessing_strategy
  • feature_subset_strategy
  • cv_metrics
  • selected_threshold
  • guidance_metric_value

6.5 查看最佳配置

cat experiments/outputs/explore-clear/best_config.json
cat experiments/outputs/explore-clear/metrics.json
当前 CLI explore 没有暴露 --k-folds、--target-specificity、--threshold-policy 等参数；底层 harness 已有字段，后续可以把这些选项补到 CLI。

14. 常见问题

14.1 提示 LLM provider is not configured

检查 .env 是否包含：

MLAGENT_LLM_PROVIDER_NAME=minimax
MLAGENT_LLM_API_PROTOCOL=openai-completions
MLAGENT_LLM_BASE_URL=https://api.minimaxi.com/v1
MLAGENT_LLM_API_KEY_ENV=MINIMAX_API_KEY
MINIMAX_API_KEY=你的key
MLAGENT_LLM_MODEL=MiniMax-M2.7

14.2 MiniMax 返回 401

在 OpenAI-compatible 模式下，当前项目使用 Authorization: Bearer。请确认：

  • MLAGENT_LLM_API_PROTOCOL=openai-completions
  • MLAGENT_LLM_BASE_URL=https://api.minimaxi.com/v1
  • MINIMAX_API_KEY 没有被截断。

14.3 MiniMax 返回内容带 think 标签

当前客户端已过滤 <think>...</think>。如果仍看到该标签，请确认运行的是最新代码并重新跑：

uv run pytest tests/contract/test_foundation_contracts.py::test_llm_client_stream_strips_openai_reasoning_tags -q

14.4 /train_type1 在默认 shell 中不能真正执行

这是当前产品化缺口：默认 shell 尚未装配 RunService 和 harness registry。请先用 one-shot CLI 的 explore 测真实训练链路，用 pytest 验证 /train_type1 路由。

14.5 reproduce one-shot CLI 返回 2

当前 main 的 reproduce 分支只在测试中通过 factory 注入执行器。真实复现请先用 StrictSkillReproductionAdapter 服务层 snippet 或对应 pytest。

14.6 uv 缓存权限错误

如果在 Codex 沙箱中看到 Failed to initialize cache，这是沙箱访问用户缓存目录的限制。普通终端中通常直接运行即可；Codex 内需要授权 uv run。
