## 二、底层架构分析

### 2.1 智能体架构模式

目前主流产品采用三类架构，实际系统常混合使用：

#### 模式 A：ReAct（推理-行动交替）
- **代表**：FAMOSE、MLAgentBench 中的所有被测 Agent
- **工作方式**：LLM 在每一步先推理（Thought）→ 选择工具（Action）→ 观察结果（Observation）→ 循环
- **记忆方式**：依赖上下文窗口（隐式短期记忆），不跨会话持久化
- **适用场景**：特征工程探索、单次实验优化
- **证据**：FAMOSE 论文明确采用 Smolagents 框架实现 ReAct，上下文记录"什么特征有效/无效"作为类少样本学习

#### 模式 B：Plan-and-Execute（计划-执行分离）
- **代表**：MLR-Copilot、RD-Agent、LightAutoDS-Tab
- **工作方式**：Planning 阶段生成完整执行计划 → Execution 阶段逐步实施 → Feedback 阶段评估并触发重规划
- **记忆方式**：RD-Agent 从论文/报告提取知识构建知识库；MLR-Copilot 用 HuggingFace 检索候选代码/模型
- **适用场景**：多步 ML 研究流程、需要先验知识导入的场景

#### 模式 C：树搜索（Tree Search）
- **代表**：AIDE
- **工作方式**：将候选解组织为树结构，LLM 基于单个节点提出改进方案；策略性复用有希望的子树；自动评估驱动搜索
- **记忆方式**：树节点即"经验库"，历史实验结果内嵌于树结构
- **优势**：不依赖上下文窗口长度；可回溯；累积改进有数学保证
- **证据**：AIDE 论文称"reusing and refining promising solutions effectively trades compute for performance"

#### 模式 D：多 Agent 并行（Multi-Agent）
- **代表**：MALMAS、LightAutoDS-Tab、CellAtria、AgentHPO
- **工作方式**：专职子 Agent 负责不同维度（如不同特征类型、不同 AutoML 框架），Router Agent 动态调度，Supervisor/Summary Agent 汇聚知识
- **记忆方式**：MALMAS 有三层记忆（过程记忆/反馈记忆/概念记忆），Summary Agent 将跨 Agent 经验提炼为全局概念记忆
- **适用场景**：特征空间覆盖全面性要求高、需要不同专业知识并行的场景

### 2.2 自主探索优化方向的机制

| 机制 | 代表产品 | 实现方式 |
|------|---------|---------|
| **搜索空间设计** | AIDE、FLAML | AIDE 用代码空间树搜索；FLAML 用 FLAML-based 搜索框架 + LLM 建议 |
| **奖励反馈** | ML-Agent | RL 训练，统一奖励函数（编译错误/资源失败/性能指标 → 标量），Step-Wise RL 解耦采样与训练 |
| **验证集驱动** | FAMOSE、MALMAS | 每轮生成特征后立即在验证集上测试，性能变化作为奖励信号反馈给 LLM |
| **预算感知** | Dataforge、AgentHPO | 预算反馈循环（budgeted feedback loop），自动停止条件 |
| **假设驱动** | RD-Agent、MLR-Copilot | LLM 生成科学假设 → 实现 → 实验验证 → 新假设；类科学家工作循环 |

### 2.3 记忆/经验系统设计

MALMAS 提供了目前已知最完整的三层记忆架构，可作为参考：

```
过程记忆（Procedural Memory）
  └─ 记录已执行的变换操作，防止重复探索

反馈记忆（Feedback Memory）
  └─ 将生成的特征与下游验证结果关联，显式信用分配

概念记忆（Conceptual Memory）
  └─ 从历史表现模式中提炼可复用启发规则
     ↓ 由 Summary Agent 汇聚为
全局概念记忆（Global Conceptual Memory）
  └─ 跨 Agent 共享，促进知识迁移，减少重复
```

其他产品的记忆方案：
- **RD-Agent**：从文献/报告提取知识 → 执行反馈 → 迭代精炼，属于"外部知识 + 执行经验"混合型
- **AIDE**：树结构本身即记忆，历史实验结果以节点形式保留
- **AutoSkill**（参考）：将可复用能力晶化为显式 `SKILL.md` 文件，版本演化管理 — 与目标产品"skill 模式"完全吻合
- **FAMOSE**：上下文窗口隐式记忆，不跨会话持久化，是最轻量但也最受限的方案

### 2.4 前沿技术检索能力

- **RD-Agent**：已实现从学术论文中提取特征/模型设计，直接转化为可执行代码，属于"文献 → 知识库 → 自动实现"的完整链路
- **MLR-Copilot**：IdeaAgent 基于已有论文生成新研究想法，ExperimentAgent 从 HuggingFace 检索候选实现
- 主流产品中**尚无产品**面向 NGS 领域实现"定期检索前沿特征工程算法"的主动技术更新机制，这是目标产品的差异化机会
- **NGS 领域现状**：muyu-search 搜索确认，截至 2025 年，超过 60% 的生命科学研究团队已将 AI/ML 嵌入数据工作流（来源：LinkedIn 业界分析），说明目标用户群已具备 AI 工具使用基础

### 3.3 目标产品交互模式建议

基于以上调研，**推荐采用「Jupyter Notebook 嵌入式 Chat + Web 仪表板」双模交互**：

- **主界面**：Jupyter AI 风格的 Chat 侧边栏，嵌入用户现有 notebook 工作流（NGS 研究员已大量使用 notebook）
- **探索模式**：用户上传数据/描述任务 → Agent 自主运行多轮实验 → 在 Chat 中汇报进展 + 将关键代码插入 notebook
- **Skill 复用**：Web 仪表板展示已有 skill 库（类似 DataRobot 模型排行榜），用户单击即可触发
- **交互式迭代**：Chat 窗口中直接发送"换一个算法试试"/"重点优化召回率"等指令，Agent 实时响应
- **经验积累展示**：Web 端知识库视图，展示已积累的特征工程经验、最佳参数配置、文献摘要

## 四、智能体案例参考

### 4.1 已有的「外部工具调用 + Harness 架构」Agent 案例

#### SWE-agent（Princeton，2024）
- **链接**：[arxiv](https://arxiv.org/abs/2405.15793)
- **核心创新**：提出 Agent-Computer Interface（ACI）概念 — 专为 LLM 设计的工具接口抽象层，区别于为人类设计的 Linux shell。发现定制 ACI 可显著超越通用 shell 接口
- **架构**：LLM 调用受控 bash 命令集（文件查看、搜索、编辑、执行）→ 获得结构化观察 → 下一步推理
- **性能**：NeurIPS 2024 发表；SWE-bench 上实现 12.5% 解决率
- **对本产品借鉴**：为 ML 工程任务设计专属 ACI（如 `run_experiment`、`compare_features`、`search_literature` 等专用工具），而非让 Agent 直接操作通用 shell

#### OpenHands（2024-2025）
- **链接**：[arxiv](https://arxiv.org/abs/2511.03690) / [GitHub](https://github.com/All-Hands-AI/OpenHands)
- **架构**：事件溯源状态模型（Event-Sourced State）；`Agent → Actions → Environment → Observations → Agent` 循环；每会话独立 Docker 沙箱（SSH + Jupyter kernel + 浏览器）；Action-Execution-Observation 三段合约；MCP 工具与原生工具统一接口
- **关键设计**：不可变事件日志支持确定性回放（断点续接）；上下文压缩管理 token 预算；多 LLM 路由（文本 vs 图像 vs 成本优化）
- **性能**：SWE-Bench-Full 上 SOTA；支持 15 个不同 benchmark
- **对本产品借鉴**：Docker 沙箱隔离 ML 实验环境是最佳实践；事件溯源设计支持实验重放和调试；MCP 集成方式可用于连接 NGS 数据管道工具

#### Devin（Cognition AI，2024）
- **链接**：[cognition.ai](https://www.cognition.ai/blog/introducing-devin)
- **架构**：持久化工作空间（shell + 浏览器 + 代码编辑器）；长期规划能力；可自主调试运行错误
- **性能**：SWE-bench 上 13.86% 解决率（首个商用 AI 软件工程师）
- **对本产品借鉴**：持久化工作空间 = 持久化实验上下文，是跨会话经验积累的基础设施

#### Claude Code（Anthropic，2024-2025）
- **链接**：[claude.ai/claude-code](https://claude.ai/claude-code)
- **架构**：CLI 工具；直接访问本地文件系统和 shell；Agent SDK 支持多 Agent 编排；MCP 协议统一工具接口
- **对本产品借鉴**：Claude API + Agent SDK 是本产品的优先技术选型（见 `CLAUDE.md` 项目说明）；MCP 可接入 muyu-search 等外部数据源

#### AIDE（Weco AI，2024-2025）
- **链接**：[arxiv](https://arxiv.org/abs/2502.13138)
- **架构**：树搜索 Agent；每个"节点"是一个完整 ML 解决方案代码文件；LLM 基于节点提出改进 → 执行 → 评估 → 添加新节点；自动量化评估（validation metric）驱动搜索
- **性能**：MLE-Bench 上超越人类专家解答；在 RE-Bench 上 SOTA；Kaggle 任务中获得 2× 奖牌数（vs 对比 Agent）
- **对本产品借鉴**：树搜索作为"探索模式"的核心算法，历史节点即"经验库"的天然实现

### 4.2 这类 Agent 已做到什么程度

| 能力维度 | 当前水平 | 代表证据 |
|---------|---------|---------|
| 自主完成 Kaggle 竞赛 | 达到或超越人类中等水平 | AIDE 在 Kaggle 任务获 SOTA；LightAutoDS-Tab 均分 0.839 |
| 自主 ML 实验循环 | 可自主执行数十轮迭代 | FAMOSE 20 轮×10 步；AIDE 树搜索无限制 |
| 从文献提取知识实现 | 初步实现 | RD-Agent 从财务报告/论文提取，MLR-Copilot 从 HuggingFace 检索 |
| 跨任务经验复用 | 初步实现（MALMAS 概念记忆） | MALMAS Summary Agent 提炼全局启发规则 |
| NGS/生物信息专项 | 刚起步 | CellAtria（scRNA-seq 标准流程），DeepSeq（细胞标注） |
| 完全自主特征工程 | 在通用数据上 SOTA | MALMAS 分类均值排名 1.12；FAMOSE RMSE 降低 2% |
| 用户自然语言交互调整 | 部分实现 | AgentHPO Creator Agent、CellAtria Chat |

## 五、核心结论（给决策汇总用）

### 5.1 市场空白确认

目前**没有任何产品**同时满足以下全部条件：
1. 面向 NGS/生物信息 ML 模型训练（CellAtria 最近，但不做训练优化）
2. 具备跨会话持久化经验库（MALMAS 最接近，但无产品化）
3. 支持 ipynb 和文献导入（RD-Agent 支持文献，但无 NGS 场景）
4. 提供 skill 复用机制（AutoSkill 概念最接近，但无产品）
5. 聊天式交互实时迭代（部分产品有，但无 NGS 专项）

**结论：目标产品在 NGS 领域 ML 训练 AI 助手方向具备明确的差异化空间。**

### 5.2 推荐借鉴的架构组合

| 功能模块 | 借鉴来源 | 理由 |
|---------|---------|------|
| 探索模式核心算法 | AIDE 树搜索 | 历史实验天然形成经验库；可回溯；自动评估驱动 |
| 多层记忆体系 | MALMAS 三层记忆 | 过程/反馈/概念三层覆盖短期→长期经验 |
| Skill 复用机制 | AutoSkill SKILL.md + RD-Agent | 将成功范式晶化为可复用显式文件 |
| 文献导入 | RD-Agent + MLR-Copilot | 已有从论文提取知识并实现的完整链路 |
| 工具 Harness | OpenHands + SWE-agent ACI | Docker 沙箱 + 专属 ML 工具接口 |
| 交互模式 | Jupyter AI + CellAtria | Chat 嵌入 notebook + NGS 领域对话驱动先例 |

### 5.3 技术选型建议

- **Agent 核心**：Claude API + Anthropic Agent SDK（项目已定）
- **工具接口**：MCP 协议（已有 muyu-search-mcp，可扩展 NGS 数据工具）
- **执行沙箱**：Docker 容器（参考 OpenHands/CellAtria 先例）
- **记忆存储**：分层存储 — 短期用上下文窗口，中期用 SQLite/JSON 结构化存储，长期用向量库（概念记忆 RAG 检索）
- **UI**：第一阶段 CLI/Jupyter 插件优先，第二阶段 Web 仪表板

### 5.4 主要风险

1. **NGS 特征工程领域知识**：通用 AutoML Agent 缺乏 NGS 专业知识（变异过滤、测序深度、批次效应等），需要专项提示/工具封装
2. **计算成本**：FAMOSE 等方案计算开销大（20 轮×10 步），NGS 数据集通常更大，需要高效的早停策略
3. **文献检索质量**：RD-Agent 在量化金融文献质量有限，NGS 文献格式（方法节、补充材料）解析需要专项处理
