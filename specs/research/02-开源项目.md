### 项目 1：AIDE (AI-Driven Exploration)

- **GitHub**：https://github.com/WecoAI/aideml
- **Stars**：1,285 | **最近 commit**：2026-05-02 | **License**：MIT
- **技术栈**：Python 3.10+，支持 OpenAI / Anthropic / Gemini / Ollama 后端，Streamlit UI，PyPI 分发
- **核心能力**：
  - 树搜索（tree search）驱动的自主 ML 代码生成与迭代优化
  - 每个 Python 脚本作为解决方案树的节点，自动 draft → debug → benchmark 循环
  - 指标驱动（最大化/最小化任意用户指定指标）
  - HTML 可视化 + Streamlit 界面检视解决树
  - OpenAI MLE-Bench（75 个 Kaggle 赛题）中，AIDE 树搜索比最佳线性 agent（OpenHands）多获 4× medal
- **短板**：
  - 本地模型性能有所下降（依赖 API）
  - 无原生记忆系统，每次从头探索
  - 无 ipynb 导入 / 文献导入能力
  - UI 较简陋（Streamlit 原型级别）
- **可复用模块**：
  - **探索引擎**（树搜索 + 代码生成 + 评估循环）— 直接覆盖「探索模式」核心
  - YAML 配置预设 + CLI 接口设计模式
- **集成难度**：拆出来用（核心探索逻辑可提取，但需要接入记忆系统和 harness）
- **为什么/为什么不 fork**：AIDE 探索引擎是目前开源中最成熟的 LLM 驱动 ML 自主探索实现，且 MIT 许可。建议 fork 后：①接入 mem0 记忆层；②替换 harness 为 Claude Code CLI；③扩展 ipynb 导入接口。

### 项目 3：CAAFE (Context-Aware Automated Feature Engineering)

- **GitHub**：https://github.com/noahho/CAAFE
- **Stars**：192 | **最近 commit**：2024-12-20 | **License**：Apache-2.0
- **技术栈**：Python，GPT-4/GPT-3.5，TabPFN，scikit-learn，PyTorch
- **核心能力**：
  - LLM 基于数据集描述迭代生成语义化新特征
  - 交叉验证自动评估新特征质量，并将结果反馈给 LLM
  - 在 11/14 数据集上提升 ROC AUC（0.798 → 0.822）
  - 安全白名单：只允许执行预定义的 Python 操作子集
- **短板**：
  - 仅做特征生成，无自主探索主循环、无记忆系统
  - TabPFN 变体只适合小型数据集
  - 不支持大型基因组数据集（内存限制）
  - 每 10 次迭代消耗约 \$0.50 GPT-4 费用
  - Stars 极少（192），维护频率低
- **可复用模块**：
  - **LLM 驱动特征生成 + 交叉验证反馈循环**（适合 NGS 表达量/突变特征工程）
  - 安全代码执行白名单机制
- **集成难度**：拆出来用（特征生成模块可作为探索模式的一个子工具）
- **为什么/为什么不 fork**：不 fork，但核心 LLM→生成特征→CV评估→反馈 的循环设计值得借鉴，作为探索模式中「特征工程子任务」的实现参考。

## 三、推荐组合方案

### 核心架构：Claude Code CLI as Harness

本项目的 harness 已确定为 Claude Code CLI，不需要也不应该引入 OpenHands 或 Letta 作为 runtime 替代。所有其他项目都以「组件」身份集成。

### 推荐组合（4 层）

```
┌─────────────────────────────────────────────────────┐
```

## 四、核心结论（给决策汇总用）

1. **探索模式：AIDE 是最佳起点**。唯一经 Kaggle benchmark（MLE-Bench 75 赛题）验证的开源 LLM 树搜索 ML 探索引擎，MIT 许可，1.3K Stars，2026年5月仍在更新。建议 fork 后将 harness 替换为 Claude Code CLI，接入记忆系统。

2. **记忆系统：mem0 + MLflow 双层组合**。mem0（56K Stars，Apache-2.0）提供语义检索和多级记忆，MLflow（26K Stars，Apache-2.0）提供结构化实验追踪，两者互补，都是 pip install 直接集成，无 fork 成本。

3. **Skill 模式：Claude Code 内置能力，无需引入新框架**。Claude Code CLI 的 `~/.claude/skills/` 体系天然支持可复用范式，notebook-intelligence 已验证了 Claude Code + JupyterLab 集成的可行性。

4. **交互训练：jupyter-ai MCP server + notebook-intelligence 参考实现**。ipynb 导入功能通过 Jupyter MCP server 实现，交互式训练通过 Claude Code CLI 的交互模式实现。notebook-intelligence 为 GPL-3.0，内部使用不触发 copyleft，可直接复用代码。

5. **最大风险点**：
   - AutoML-Agent（ICML 2025）CC BY-NC 许可不可商用
   - notebook-intelligence GPL-3.0：内部使用已无风险，可直接复用
   - OpenFE 和 CAAFE 社区活跃度低，长期维护存疑
   - Letta 和 OpenHands 与 Claude Code harness 存在架构冲突，不要引入为 runtime

6. **NGS 特化空白**：所有调研项目均为通用 ML 框架，无 NGS 特化项目。NGS 特化部分（BAM/VCF 读取、序列特征提取、基因组注释）需自研或封装 bioinformatics 工具（如 pysam、pyranges、biopython）作为 agent 工具库，不在开源 ML agent 生态中。
