训练实例固化为可完整复现的 SOP 与模型版本。

### 1.1 术语

| 术语 | 定义 |
| --- | --- |
| 原始记录 | 对一次探索及其训练实例的关键事实和必要证据，不等于完整会话日志 |
| 训练实例 | 在冻结的数据、代码、配置、环境和随机种子下实际执行的一次训练 |
| 经验 | 从历史事实提炼的专家知识，用于指导后续探索，不是 SOP 的来源 |
| SOP | 从指定训练实例形成、经独立复现和人工批准的完整训练方法 |
| 正式模型 | 与已批准 SOP 版本绑定并进入正式模型版本库的模型 |
| 低置信度经验 | 已提取但尚未完成人工审核的经验候选 |
| 权威资产 | 团队共享 Git 仓库中的结构化文件及受管附件 |
| 本地索引 | 从权威资产派生、可删除并重建的查询加速数据 |

## 2. 背景与目标

### 2.1 背景

模型探索常散落在会话、Notebook、临时脚本和结果目录中。团队难以回答以下问题：

- 某个结果究竟使用了哪一版数据、代码、参数和环境。
- 一次成功或失败为后续探索提供了什么可复用知识。
- 某个训练方法是否被真实复现，能否作为团队 SOP 使用。
- 正式模型对应哪一版 SOP，为什么做过这些优化。
- 多人协作时如何只同步差异，同时避免覆盖他人的资产。
- 训练过程中如何实时检查代码、运行方向和性能变化。

### 2.2 产品目标

1. 建立解耦、可复用、可视化的团队记忆库，覆盖原始事实、专家经验、SOP 和正式模型。
2. 让所有关键训练结果具备完整版本和谱系，可从结果回溯到本源证据。
3. 让经验在人工治理下持续服务新探索，使插件随团队实践积累而提升决策质量。
4. 将指定训练实例或经复现的 Notebook 固化为可严格复现的 SOP。
5. 通过 Claude Code Skills 与 Hooks，把“认知、设计、执行、记录、审核、同步”串成闭环。
6. 通过六个聚焦的 UI 模块支持代码审核、数据认知、实时运行、SOP、经验和谱系查看。

### 2.3 设计原则

- **事实与推断分离：** 原始事实、经验和 SOP 是不同资产，不能互相替代。
- **先设计后执行：** 用户未确认探索方案前不得开始正式训练。
- **不可变版本：** 已提交资产不原地覆盖；变更创建新版本或勘误记录。
- **人机共治：** 经验与 SOP 都经过人工决策门，自动化不替代最终审批。
- **Git 原生：** 权威资产进入一个团队共享普通 Git 仓库，只同步差异对象。
- **最少记录：** 默认只保存能够复现、解释或审核结果的关键事实。
- **界面不越权：** UI 通过统一领域能力写入，不直接改写权威文件。

## 3. 目标用户与角色

### 3.1 主要用户

| 角色 | 核心任务 | 主要痛点 | 所需能力 |
| --- | --- | --- | --- |
| 生物信息/算法工程师 | 导入特征数据、设计并运行分类模型探索 | 实验散乱、难复现、代码难实时审查 | 数据认知、训练探索、代码审核、结果回溯 |
| 高级研究员/项目负责人 | 审核经验和 SOP、比较历史策略、控制团队标准 | 难判断经验可信度和模型来源 | 审核、版本比较、谱系、正式模型治理 |
| 团队协作者 | 复用既有 SOP，在新增样本或类似项目上重训练 | 同步冲突、误覆盖正式资产 | 增量 Git 同步、严格 SOP 执行、候选结果隔离 |

### 3.2 权限角色

| 权限角色 | 权限范围 |
| --- | --- |
| 使用者 | 查看资产、创建探索、运行训练、提出经验和 SOP 候选 |
| 授权审核者 | 具备使用者权限，并可批准、修改或拒绝经验与 SOP 候选 |
| 仓库维护者 | 管理远端地址、SSH 接入、成员权限、冲突处理和仓库容量 |

任意一名授权审核者可以批准经验或 SOP。所有审批必须留下审核者、时间、输入版本和结论。

### 3.3 非目标用户

- 需要从原始测序数据完成全流程 NGS 处理的用户。
- 以深度学习、大规模 GPU 调度或分布式训练为核心的团队。
- 需要公网多租户 SaaS、在线 Notebook 托管或通用 MLOps 平台的用户。

### 4.2 典型场景

**场景 A：从新数据开始探索**

用户启动项目，插件先增量同步共享记忆库，再识别数据和任务。插件检索可信经验及明确
标注的低置信度经验，生成探索方案供用户确认。训练按轮次执行，每轮形成训练实例并在
UI 实时展示。会话结束后封口记录、提取经验候选并同步新增资产。

**场景 B：将最佳实例固化为 SOP**

用户指定一次训练实例。系统检查证据完整性，生成 SOP 候选，在相同数据、代码、配置和
环境下独立复现。只有主指标六位小数完全一致并经授权者批准后，才创建正式 SOP 和正式
模型版本。

**场景 C：将人工 Notebook 转成 SOP**

用户导入 Notebook。系统解析步骤、依赖和隐含条件，补齐必要执行信息并先运行成一个
训练实例。解析或复现失败时只保存失败证据；复现成功后，用户才能继续发起 SOP 流程。

**场景 D：在新增样本上复用 SOP**

用户选择 SOP 与新数据版本发起重训练。系统严格执行 SOP 并生成新运行、训练实例和候选
模型，不自动更新原 SOP 或正式模型库。用户可另行发起新 SOP 版本审批。

## 5. 功能范围与非范围

### 5.1 MVP 范围

| 能力域 | MVP 范围 |
| --- | --- |
| 产品入口 | Claude Code 插件、命令、Skills、Hooks、本地 Web UI |
| 数据 | 结构化特征矩阵、标签、拆分文件及标准化数据版本 |
| 任务 | 二分类、多分类；用户确认评价指标和目标性能 |
| 探索 | 先设计后探索、按轮训练、代码冻结、指标跟踪、人工停止与调整 |
| 原始记录 | 关键决策、方案、代码、配置、环境、指标、失败、结论和必要证据 |
| 经验 | 自动提取候选、低置信度使用、人工审核、版本与替代关系 |
| SOP | 指定实例转 SOP、Notebook 先复现、独立复现门、人工批准、版本管理 |
| 模型 | 运行模型保留；仅 SOP 关联模型进入正式模型版本库 |
| Git | 单一团队共享普通 Git 仓库、SSH 接入、差异同步、冲突保护 |
| UI | 代码审核、数据集概览、运行状态、SOP、经验审核、谱系回溯 |

### 5.2 明确不在 MVP 范围

- 回归、深度学习、GPU 集群和分布式训练。
- 从 FASTQ/BAM 等原始 NGS 数据开始的生信流程。
- 自动批准经验、SOP 或正式模型。
- 将 mem0、MLflow、向量数据库或 AIDE 作为必需依赖或事实来源。
- 后台无人值守的“梦境任务”、持续自主实验和自动文献调研。
- Git LFS、对象存储、多仓库联邦同步和公网远程 UI。
- 运行中的代码热替换、多人同时写同一 Claude Code UI 会话。
- 完整保存全部对话、全部工具输出或完整 stdout/stderr。

## 6. 详细功能需求

### 6.1 权威资产与数据结构

**FR-001 单一事实来源**

- 触发：任何资产创建、修改、审核或同步。
- 输入：数据集、运行、实例、经验、SOP、模型及审核动作。
- 处理：通过统一领域能力校验并创建结构化版本；本地索引只读取这些版本。
- 输出：带唯一 ID、版本、时间、创建者、状态和引用关系的权威资产。
- 边界：索引、UI 缓存和会话上下文不得反向覆盖权威资产。

**FR-002 资产不可变与版本化**

- 已提交的数据、记录、SOP 和模型文件不得原地覆盖。
- 内容变化必须创建新版本；错误通过勘误、拒绝或替代关系表达。
- 所有引用必须指向具体版本，不能只引用可漂移的名称或“最新版本”。

**FR-003 数据集版本**

- 每个数据版本保存实际标准化特征、标签、拆分、清单、任务、指标协议和内容指纹。
- 数据集默认进入团队共享 Git 仓库；单文件必须小于 100 MB。
- 标签、拆分或标准化结果变化时必须创建新数据版本。

### 6.2 记忆库初始化与增量同步

**FR-010 初始化**

- 触发：首次运行 `bootstrap-memory` 或项目尚未连接共享记忆库。
- 输入：远端仓库地址、本地目录、SSH 连接配置和成员身份。
- 处理：验证权限、建立受管目录、创建本地索引并检查容量规则。
- 输出：可用的团队记忆工作区和初始化报告。
- 边界：SSH 私钥、凭证和本地索引不得提交仓库。

**FR-011 会话开始同步**

- 触发：`SessionStart`。
- 处理：检查工作区锁，获取远端差异；本地落后时快进，本地领先时推送，双方仅新增且
  文件互不冲突时合并；随后更新本地索引。
- 输出：同步状态、待推送数量、冲突提示和待审核事项。
- 边界：禁止重新克隆、强推、自动覆盖冲突文件。

**FR-012 会话结束同步**

- 触发：`Stop` 完成运行封口后。
- 处理：只暂存插件管理路径，提交新增或变化资产并推送；推送被拒绝时重新获取差异并
  自动重试一次。
- 输出：提交引用或本地待同步状态。
- 边界：网络或冲突失败不能丢失本地资产，也不能执行全工作区暂存。

### 6.3 数据与任务认知

**FR-020 数据认知**

- 触发：用户运行 `intake-data` 或选择新的数据输入。
- 输入：特征矩阵、标签信息及可选拆分。
- 处理：识别样本与特征结构、缺失、标签列、类别分布和潜在数据问题，并提出最少必要
  澄清问题。
- 输出：数据清单、数据预览、内容指纹和待确认事项。
- 边界：不扫描与任务无关的任意目录，不把未确认推断写成最终事实。

**FR-021 任务确认**

- 系统支持二分类和多分类，必须由用户确认任务类型、正类定义、主评价指标、数据拆分和
  目标性能。
- 未完成确认时，系统可以分析数据，但不得开始正式探索训练。

### 6.4 先设计后探索

**FR-030 探索方案**

- 触发：用户运行 `design-and-explore`。
- 输入：已确认数据版本、任务、目标、资源限制、可信经验和低置信度经验。
- 处理：生成基线、探索方向、每轮假设、评价方法、停止条件和风险；分别标记可信与待审
  核经验的引用。
- 输出：可审核的探索方案记录和候选训练代码；探索方案不进入 SOP 式不可变版本库。
- 边界：用户未确认方案前，`PreToolUse` 必须阻止正式训练。
- 方案或候选代码在确认后发生变化时，原确认失效并要求重新确认。最终批准内容只在训练
  启动后冻结到对应运行和训练实例证据中；只有后续通过复现与人工审核的 SOP 才形成可
  复用的不可变方案版本。

**FR-031 训练执行与轮次**

- 每轮必须冻结数据、代码、配置、环境、随机种子和父实例引用。
- 训练执行产生状态、耗时、指标、预测、模型、错误和本轮优化方向。
- baseline、阶段最佳和用户明确标记的模型进入所属运行包；未被选中的中间模型默认不进入
  长期权威资产，只保留其指标、模型指纹和必要证据。
- 用户在 UI 修改代码时创建下一候选代码版本，不改变正在运行的实例。
- 训练失败或超时必须生成失败实例，但不得进入 SOP 生成流程。

### 6.5 原始记录与训练实例

**FR-040 最少关键记录**

系统只保存下列能够支持复现、解释或审核的事实：

- 运行身份、时间、操作者、会话引用和状态。
- 数据版本、任务、评价协议和用户批准的探索方案。
- 每轮假设、优化方向、父实例、代码版本、配置、环境和随机种子。
- 指标、预测、模型引用、错误摘要、停止原因和结论。
- 支撑人工决策、异常或结论的必要证据片段。

完整对话、无关文件查看、普通工具输出和完整日志默认不保存。长日志只保留摘要和必要
证据附件。

**FR-041 运行封口与恢复**

- `Stop` 必须校验运行和实例完整性，再将运行标为完成或失败。
- 异常退出造成未封口运行时，下次 `SessionStart` 必须提示恢复、继续或关闭。
- 已封口事实不得被后续会话静默修改。

### 6.6 经验提取与审核

**FR-050 自动提取经验候选**

- 触发：会话结束且本次存在新增训练事实。
- 输入：本次会话开始后新增的实例、指标、失败、决策和结论。
- 处理：提炼成功规律、失败模式、适用条件、推荐动作、风险和证据引用。
- 输出：一个或多个经验候选；没有有效经验时不创建空记录。
- 边界：经验不能引用不存在的证据，也不能据此生成或修改 SOP。

**FR-051 低置信度使用**

- 待审核经验可参与新探索建议，但必须显示“待审核/低置信度”、证据和风险。
- 方案必须区分可信经验与低置信度经验，用户可以排除后者。
- 低置信度经验不得作为 SOP 审批证据或自动改变正式资产。

**FR-052 人工审核**

- 授权审核者可以修改表述后批准、拒绝，或将新经验标记为对旧经验的补充、冲突或替代。
- 审核必须保留候选原文、修改内容、证据、审核者、时间和结论。
- 批准后生成可信经验版本；旧版本继续可追溯。

### 6.7 SOP 生成、复现与审批

**FR-060 SOP 来源限制**

- SOP 只能由用户指定的一个已完成训练实例发起。
- 经验、聊天总结、未执行脚本或单独模型文件不能直接成为 SOP 来源。
- 候选必须记录来源实例、数据版本、训练策略、优化背景和预期指标。

**FR-061 训练实例转 SOP**

- 触发：用户运行 `instance-to-sop` 并选择实例。
- 处理：检查代码、依赖、配置、环境、随机种子、数据拆分、指标和模型证据是否完整；将
  实例拆解为前置条件、步骤、输入、输出、验证和失败处理。
- 输出：SOP 候选或结构化缺失清单。
- 边界：证据不完整或实例失败时不得进入正式复现门。

**FR-062 Notebook 转 SOP**

- 导入 Notebook 后，系统必须解析单元格、执行顺序、外部依赖、数据路径、随机性和指标。
- 原始 Notebook、内容指纹和解析报告作为导入证据保存。
- 系统补齐必要执行描述后先运行并形成训练实例，记录解析警告和改动。
- 只有该实例成功并通过完整性检查后，用户才能按 FR-061 发起 SOP 候选。
- 解析或复现失败只保存导入记录和失败证据，不创建 SOP。

**FR-063 独立复现门**

- SOP 候选必须在相同数据、代码、配置、环境、拆分和随机种子指纹下重新执行。
- 复现任务与来源实例必须是两个不同执行记录。
- 主指标统一保留六位小数，复现值必须与来源值完全一致。
- “100% 可复现”指上述条件、步骤、输出和六位小数指标一致，不要求模型二进制哈希一致。
- 任一条件不满足或指标不一致，候选保持失败/待修订状态，不得批准。

**FR-064 SOP 审批和版本**

- 任意一名授权审核者可在复现门通过后批准 SOP。
- 正式 SOP 必须保存来源实例、独立复现实例、审批、数据版本、策略摘要和优化背景。
- SOP 修改必须生成新版本，旧版本不可覆盖；版本间需记录变更摘要。

### 6.8 模型版本与 SOP 重训练

**FR-070 模型分层**

- baseline、阶段最优和用户明确标记的运行模型保留在所属运行包；其他中间模型默认不长期
  保留。
- 正式模型版本库只保存与已批准 SOP 版本关联的模型。
- 正式模型默认采用通过独立复现门的模型；来源实例模型仍保留在来源运行包，不重复登记为
  同一 SOP 版本的正式模型。
- 正式模型必须记录 SOP、来源和复现实例、数据、性能、训练策略、优化背景和审批信息。

**FR-071 按 SOP 重训练**

- 触发：用户运行 `retrain-from-sop` 并选择具体 SOP 版本和数据版本。
- 处理：锁定 SOP 步骤和评价协议，执行兼容性检查并创建新运行。
- 输出：训练实例、指标和候选模型，以及相对 SOP 历史的性能比较。
- 边界：新数据重训练结果不得自动覆盖 SOP 或进入正式模型库；必须另行审核和版本化。

### 6.9 本地查询索引与谱系

**FR-080 可重建索引**

- 触发：同步后、资产写入后、用户手动重建或检测到索引损坏。
- 处理：从权威文件更新或全量重建本地查询索引。
- 输出：检索、状态汇总、时间线和谱系所需派生数据。
- 边界：索引不进入 Git；删除索引不能造成权威资产丢失。

**FR-081 精准谱系**

- 支持从数据、运行、实例、经验、Notebook、SOP 和模型任一节点双向追踪直接证据。
- 经验与 SOP 可以引用同一原始实例，但不得显示虚假的“经验生成 SOP”关系。
- UI 必须区分直接来源、参考关系、版本关系、审批关系和替代关系。

### 6.10 Skills 与 Hooks

**FR-090 MVP Skills**

产品提供六个工作流 Skill：

1. `bootstrap-memory`
2. `intake-data`
3. `design-and-explore`
4. `retrain-from-sop`
5. `review-experience`
6. `instance-to-sop`

Claude Code Skill 只规定触发条件、流程和人工决策门；数据解析、训练、指标和资产写入由
统一领域能力执行。训练 SOP 是领域资产，不是 Claude Code Skill。

**FR-091 Hooks**

| Hook | 必须行为 |
| --- | --- |
| `SessionStart` | 检查仓库/SSH、增量同步、更新索引、提示未封口运行和待审核项、准备 UI |
| `PreToolUse` | 阻止未确认方案训练、直接修改正式 SOP/模型、绕过统一能力写权威资产 |
| `PostToolUse` | 只捕获训练脚本修改、训练、指标和模型等关键动作 |
| `Stop` | 封口运行、校验记录、提取经验候选、提交受管差异、增量推送 |

### 6.11 代码审核与实时协作

**FR-100 代码审核工作区**

- 提供受管代码文件树、语法编辑、保存、版本差异、修改来源和历史。
- 用户可直接修改代码，也可在同一 UI 的真实 Claude Code CLI 入口输入提示词发起修改。
- Claude 的流式响应、工具状态和文件变化必须实时刷新。
- 每次保存创建新的代码版本和指纹，并记录人工或 Claude 修改来源。
- 同一工作区同一时间只允许一个具备写权限的 UI Claude 会话。

## 7. 非功能需求

### 7.1 可靠性与一致性

- NFR-001：任何同步、训练或 UI 异常均不得破坏已存在权威资产。
- NFR-002：文件冲突时停止自动推送，保留本地提交和可读冲突报告。
- NFR-003：索引可从空状态根据仓库资产完整重建。
- NFR-004：UI 不可用时，核心训练、记录和 Git 同步仍可从 Claude Code 使用。
- NFR-005：运行中代码使用冻结快照，编辑不会造成当前实例结果漂移。

### 7.2 性能与容量

- NFR-010：<100 MB 的数据集概览在本地正常环境中 3 秒内显示首屏。
- NFR-011：运行状态、代码变化和指标更新在事件产生后 2 秒内呈现在 UI。
- NFR-012：常规会话启动只同步不一致的 Git 对象，不重新下载完整仓库。
- NFR-013：单个受管文件必须小于 100 MB；仓库预计容量上限为 20 GB。
- NFR-014：达到 80% 容量时提示维护，达到上限时阻止新增大文件自动提交。

### 7.3 安全与隐私

- NFR-020：共享仓库必须使用团队授权的私有远端和 SSH 身份访问。
- NFR-021：私钥、访问令牌、个人配置和本地索引不得写入共享仓库。
- NFR-022：数据预览、日志和错误信息不得额外复制无关敏感字段。
- NFR-023：审批和代码修改动作必须具备用户身份、时间与输入版本审计。

### 7.4 可维护性与可用性

- NFR-030：权威资产使用清晰、稳定、可校验的结构，并支持向前兼容的结构版本。
- NFR-031：失败提示必须说明失败阶段、受影响资产、是否已保存和下一步动作。
- NFR-032：左侧一级导航固定为六个模块，核心状态在页面首屏可见。
- NFR-033：正式状态、候选状态、待审核状态和失败状态在文字与视觉上明确区分。

## 8. UI 与交互需求

### 8.1 全局布局与状态

- 左侧固定导航包含六个一级模块，不增加独立首页或营销页。
- 顶部上下文条显示当前工作区、数据版本、运行、同步状态和用户身份。
- 全局状态使用统一语义：未开始、待确认、运行中、成功、失败、待审核、已批准、已拒绝、
  待同步、冲突。
- 页面通过实时事件更新；断线后显示最后更新时间并允许手动刷新。

### 8.2 模块一：代码审核

- 文件树只展示本次探索相关的受管代码和配置。
- 主区域提供代码编辑器，支持打开、直接修改、保存、只读冻结版本和差异对比。
- 侧栏或底部提供真实 Claude Code CLI 会话，用户可输入提示词并查看流式输出及工具状态。
- 展示当前运行使用的冻结代码版本和最新候选版本，避免用户误以为修改已热加载。
- 训练脚本变化后自动刷新文件树、编辑器、差异和审计记录。

### 8.3 模块二：数据集概览

- 以 Pandas 风格显示头部和尾部记录，中间用省略行表示，不默认加载全部数据。
- 展示数据版本、文件、样本数、特征数、字段类型、缺失、标签分布和异常提示。
- 展示已确认任务类型、正类、多分类类别、拆分、主评价指标和目标性能。
- 未确认内容必须显示为待确认，而不是用模型推断值伪装成事实。

### 8.4 模块三：运行状态

- 展示当前已批准探索方案、运行状态、当前轮次、总耗时和停止条件。
- 每轮展示主要优化方向、父实例、指标、状态和耗时。
- 性能趋势图按时间或轮次展示，标记方案/代码/特征/参数等改动方向。
- 用户选择历史 SOP 版本后，趋势图可叠加其同指标性能基线，并展示当前最佳实例的差值。
- 突出当前最佳实例、最佳性能、目标性能及差距。
- 支持选择历史运行并按时间回放方案、代码、实例和性能变化。

### 8.5 模块四：SOP 概览

- 列表显示 SOP 名称、版本、状态、数据版本、主性能和时间。
- 详情显示来源实例、独立复现实例、训练策略、优化背景、完整步骤、环境和正式模型。
- 版本对比显示策略变化、数据变化、性能趋势和审批记录。
- 新数据重训练结果标为候选，不与正式 SOP 模型混淆。

### 8.6 模块五：经验审核总结

- 分开展示待审核、可信、已拒绝和已被替代经验。
- 候选详情显示结论、适用条件、推荐动作、风险、置信状态和直接证据。
- 授权者可编辑表述后批准、拒绝，或设置补充、冲突和替代关系。
- 在探索中使用过的低置信度经验必须可被反查。

### 8.7 模块六：谱系回溯

- 提供关系图和时间线两种视图，支持筛选资产类型、版本、时间和状态。
- 点击任一节点显示摘要，并能跳转到数据、运行、代码、证据、SOP 或模型详情。
- 不同边类型有明确图例；经验与 SOP 不显示不存在的派生关系。
- 从正式模型进入后，应在三次交互内到达 SOP、来源实例和关键原始证据。

### 8.8 写入与并发边界

- UI 只允许提交代码保存、经验审核、SOP 审批、运行控制和上下文选择等受支持动作。
- 所有写入经统一校验后形成版本和审计记录，UI 不直接编辑 Git 中的权威文件。
- 同一工作区仅一个 UI Claude 会话具备写权限；其他会话只读或等待接管。

## 9. 验收标准

### AC-01 数据与任务确认

**Given** 用户提供结构化特征和标签文件，**When** 运行数据认知，**Then** 系统显示头尾
预览、结构、标签分布、任务和指标待确认项，且确认前不能开始正式训练。

### AC-02 先设计后训练

**Given** 数据和任务已确认但方案未批准，**When** Claude Code 尝试执行训练，**Then**
系统阻止执行并提示先确认探索方案。

### AC-03 完整训练实例

**Given** 一轮训练完成，**When** 运行被记录，**Then** 实例包含数据、代码、配置、环境、
随机种子、拆分、指标、优化方向和模型引用，且可从指标跳转到这些证据。

### AC-04 最少原始记录

**Given** 会话包含大量普通文件查看和日志，**When** 会话封口，**Then** 只保留关键决策、
训练事实和必要证据，不复制完整对话与完整日志。

### AC-05 经验自动提取

**Given** 本次会话产生了有证据支持的新规律或失败模式，**When** 触发 `Stop`，**Then**
系统创建带适用条件、风险和证据的经验候选；无有效经验时不创建空记录。

### AC-06 低置信度经验边界

**Given** 经验候选尚未审核，**When** 它参与探索方案，**Then** UI 和方案明确标为低置信度，
且它不能生成、修改或批准 SOP。

### AC-07 经验审核

**Given** 授权审核者打开候选，**When** 修改后批准或拒绝，**Then** 系统保留候选原文、
修改、证据、审核者、时间和结论，批准时生成新的可信经验版本。

### AC-08 实例转 SOP

**Given** 用户指定一个成功且证据完整的训练实例，**When** 发起 SOP 生成，**Then** 系统
创建明确引用该实例的 SOP 候选；指定经验或未执行脚本时必须拒绝。

### AC-09 Notebook 转 SOP

**Given** 用户导入 Notebook，**When** 解析或复现尚未成功，**Then** 系统不得创建 SOP；
只有复现形成成功训练实例后，才能继续实例转 SOP 流程。

### AC-10 SOP 精确复现门

**Given** SOP 候选具备完整证据，**When** 在相同指纹条件下独立执行，**Then** 只有主指标
六位小数完全一致时复现门通过；不一致时禁止批准。

### AC-11 SOP 与模型版本

**Given** 复现门通过且授权者批准，**When** 正式版本创建，**Then** SOP 和正式模型分别
获得不可变版本，并记录来源实例、复现实例、数据、策略、优化背景和审批。

### AC-12 SOP 新数据重训练

**Given** 用户选择正式 SOP 和新数据版本，**When** 重训练完成，**Then** 结果只进入新运行
和候选模型，不自动覆盖 SOP 或进入正式模型库。

### AC-13 Git 增量同步

**Given** 本地与远端仅有部分不一致内容，**When** 会话开始同步，**Then** 系统只获取或
推送差异对象，不重新克隆完整仓库。

### AC-14 Git 冲突和断网

**Given** 远端不可用或同一权威文件发生冲突，**When** 自动同步，**Then** 系统不强推、
不覆盖，保留全部本地资产并显示待同步或冲突状态。

### AC-15 代码编辑冻结边界

**Given** 一轮训练正在运行，**When** 用户或 Claude 在 UI 保存代码，**Then** 系统创建新
代码版本，当前训练仍引用旧冻结版本，下一轮才可选择新版本。

### AC-16 UI 实时状态

**Given** 训练产生新轮次、指标或代码变化，**When** UI 在线，**Then** 对应模块在 2 秒内
刷新，且最佳实例、目标差距与改动方向同步更新。

### AC-17 谱系精准回溯

**Given** 用户打开一个正式模型，**When** 进行谱系回溯，**Then** 三次交互内可到达关联
SOP、来源实例和关键证据，且不显示“经验生成 SOP”的错误关系。

### AC-18 索引重建

**Given** 本地索引被删除或损坏，**When** 用户重建索引，**Then** 系统从 Git 权威资产恢复
查询、状态、时间线和谱系，且不修改权威资产。

## 10. 优先级与 MVP 分期

### 10.1 P0：可信记忆闭环

- Claude Code 插件骨架及六个 Skills/Hooks 契约。
- 团队共享仓库初始化、增量同步、冲突保护和本地索引。
- 数据与任务认知、方案确认、训练实例及原始关键记录。
- 经验候选自动提取、低置信度使用和人工审核。
- 最小可用的数据、运行和经验查看能力。

### 10.2 P0：SOP 与正式模型闭环

- 指定实例转 SOP、Notebook 解析与先复现。
- 独立复现门、六位小数一致、人工审批和版本管理。
- 仅 SOP 关联模型进入正式模型库。
- 按 SOP 严格重训练及候选结果隔离。

### 10.3 P1：完整六模块 UI

- 代码审核与真实 Claude Code CLI 入口。
- 数据集概览、实时运行状态与历史回放。
- SOP 概览、经验审核总结和谱系图/时间线。
- 实时事件、写入审计和单写会话控制。

### 10.4 P2：后续增强

- 可选语义检索、更多分类算法适配和跨项目经验导入。
- 仓库归档与历史大资产迁移工具。
- 在不改变事实来源的前提下接入可选实验搜索引擎。

## 12. 依赖与约束

### 12.1 外部依赖

- 本地可用的 Claude Code 及其插件、Hooks 和终端能力。
- 团队可访问的私有普通 Git 远端与有效 SSH 身份。
- 可执行目标训练脚本的本地 Python 环境和所需分类算法依赖。
- 支持本地 Web UI 的现代桌面浏览器。

### 12.2 产品约束

- 所有数据、原始记录、经验、SOP 和保留模型进入同一个团队共享记忆仓库。
- 插件代码仓库与团队记忆仓库分离，避免产品代码和业务资产生命周期互相干扰。
- 不使用 Git LFS；单文件小于 100 MB，仓库长期规模控制在 20 GB 内。
- SOP 的六位小数精确复现只对相同数据、代码、配置、环境、拆分和随机种子成立。
- 训练只覆盖结构化特征输入的二分类和多分类。
- 正式审批需要稳定成员身份；Git 提交身份不能代替产品内审批记录。

### 12.3 数据与合规约束

- 数据拥有者必须确认共享仓库成员有权访问项目数据和模型。
- 仓库备份、远端保留周期和成员撤权由团队仓库治理流程负责。
- 产品不得自动将团队数据、代码或记忆上传到未授权的第三方存储。

## 13. 风险、处理策略与待验证项

| 风险/待验证项 | 影响 | 当前处理策略 | 关闭时点 |
| --- | --- | --- | --- |
| Web UI 中真实 Claude Code CLI 的连接与恢复机制 | 影响代码审核核心体验 | Phase 0 做技术验证；必须支持单写会话、流式状态和断线恢复 | UI 开发前 |
| 跨机器环境差异导致六位小数不一致 | 阻止 SOP 批准 | 记录环境/平台指纹；环境不兼容时明确判定不具备审批条件 | SOP 门开发前 |
| 普通 Git 长期保存数据和模型导致仓库膨胀 | 同步变慢、接近容量上限 | 80% 预警、100 MB/20 GB 硬门、提供只新增不覆盖的归档流程 | Phase 1 压测时 |
| 多人对同一资产并发修改 | 冲突或错误覆盖 | 唯一 ID、追加优先、本地锁、冲突停止和禁止强推 | Git 验收时 |
| 自动经验提取产生重复或错误知识 | 降低探索质量 | 保留证据、低置信度标识、人工审核和替代关系 | 经验验收时 |
| Notebook 隐含状态无法复现 | 无法形成 SOP | 显式解析告警；先形成真实实例，失败即终止 SOP 流程 | SOP 验收时 |
| 审核者身份与权限映射不明确 | 审批审计不可靠 | MVP 使用仓库配置的授权成员名单，并记录稳定用户 ID | Phase 1 启动前 |
| UI 与权威文件状态短暂不一致 | 用户误判结果 | UI 显示同步时间和版本；写入只经统一能力；索引可重建 | UI 验收时 |

本轮未决事项均为技术验证或部署配置，不改变已确认的产品边界。任何验证失败都应更换
实现方式，不得降低 SOP 复现门、资产不可变性或人工审批要求。
